# LSCG — Large‑Scale Constraint Generation: Can LLMs Parse Hundreds of Constraints?

**О чём:** постановка задачи и экспериментальная проверка того, как LLM справляются с
**сотнями/тысячами ограничений**, и как помогает предварительная фильтрация релевантных ограничений.

## Файлы в папке

- `paper_en.pdf` — версия статьи (EN, PDF)
- `paper_ru.md` — русская версия: перевод аннотации + конспект ключевых идей
- `paper_ru.pdf` — то же в PDF‑формате

## Источники

- arXiv: https://arxiv.org/abs/2509.24090  
- Примечание: PDF в этой папке может быть версией с double‑blind (анонимизированной) рецензией.

## Почему это важно для AI‑First

В инженерной практике «список ограничений» часто большой:
стандарты код‑стайла, правила интерфейсов, требования к логированию,
ограничения по производительности, регуляторика, ИБ и т.д.

Работа показывает типичный эффект: при росте числа ограничений качество резко падает.
Но есть и важная идея: если сначала выделить **релевантные** ограничения,
модель работает заметно лучше.

## Практические выводы

- Перед генерацией/планированием полезно делать этап **constraint filtering**:
  выделить релевантные требования (по задаче, модулю, изменяемым файлам).
- RAG/поиск по стандартам и документации — это частный случай такой фильтрации.
- Если ограничений сотни — делайте pipeline: (1) отбор → (2) генерация → (3) верификация.
