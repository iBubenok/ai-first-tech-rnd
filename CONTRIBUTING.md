# Contributing / Как добавлять материалы

Этот репозиторий — рабочая библиотека материалов по AI‑First: методология, практики, шаблоны,
пилоты, обучающие материалы и подборки исследований.

Пожалуйста, добавляйте материалы так, чтобы ими было удобно пользоваться, их можно было воспроизвести,
а риски по безопасности и утечкам данных были минимальны.

## 1) Куда класть материалы

- **Базовые документы, политики, методология** → `docs/`
- **Материалы конкретных направлений/продуктов** → `initiatives/<initiative>/`
- **Плейбуки (практические инструкции)** → `playbooks/`
- **Пилоты и кейсы** → `pilots/`
- **Шаблоны артефактов** → `templates/`
- **Слайды, конспекты, демо, knowledge transfer** → `materials/`
- **Подборки статей/бенчмарков** → `research/`
- **Скрипты/утилиты** → `tools/`

## 2) Минимальный набор метаданных

Для любой новой папки/материала добавьте `README.md` и укажите:

- **что это** и для кого;
- **дата** (когда актуализировано) и автор/контакт (владелец материала);
- **уровень распространения** (публичный/внутренний). Если внутренний — убедитесь, что материал допустим к размещению;
- если материал описывает практику/процесс — **Definition of Done, метрики, ограничения и риски**.

## 3) Требования по безопасности

Перед публикацией убедитесь, что в репозиторий **не попали**:

- исходники/HDL/netlist, приватные спеки, логи с чувствительной информацией;
- данные по контрактам/заказчикам, персональные данные;
- секреты (ключи, токены, пароли), внутренние URL и адреса инфраструктуры;
- идентификаторы проектов/систем, которые позволяют деанонимизировать внутренний контур.

См. также: [Политика данных и безопасность](docs/policies/data-policy-and-security.md)

## 4) Стиль и именование

- Предпочитайте **латиницу + kebab-case** в путях (например, `how-many-instructions-can-llms-follow/`).
- Для документов используйте Markdown (`.md`), где это возможно.
- Для больших бинарников (PDF/видео/слайды) держите рядом краткий `README.md` с контекстом и ссылками.

## 5) Как вносить изменения (рекомендованный процесс)

1) Создайте ветку (feature branch)
2) Добавьте/обновите материалы
3) Проверьте, что ссылки в `README.md` работают
4) Откройте merge request / pull request и попросите ревью

Если вы переносите материалы из закрытого контура — обязательно выполните **санитизацию**:
удалите/замените внутренние имена, адреса, ссылки и любые данные, которые не должны попадать наружу.
