# AI‑First: политика данных и безопасность

Цель документа — зафиксировать минимальные правила, которые позволяют использовать AI‑инструменты,
не нарушая требования к конфиденциальности, IP и внутренним регламентам.

## 1) Что **нельзя** отправлять во внешние AI‑сервисы

- исходники, HDL, netlist, спеки, отчёты, логи с чувствительной информацией;
- данные по контрактам/ОКР/заказчикам;
- всё, что может раскрыть IP или внутреннюю архитектуру.

## 2) Как обсуждать задачу безопасно

Если нужно получить помощь/идею:

- используем **redaction** (удаляем имена/пути/ключи/номера проектов/адреса/привязки);
- применяем **синтетические примеры** и минимальные воспроизводимые фрагменты;
- по возможности работаем во **внутреннем/локальном контуре** (где это разрешено политиками).

## 3) Quality gates обязательны

Любой результат от LLM:

- проходит проверки: тесты, статанализ, бенчи/профилирование, ревью;
- фиксируем решения и версии (для воспроизводимости).

## 4) Если сомневаетесь

1) Считайте данные **чувствительными по умолчанию**.  
2) Спросите у владельца данных/ИБ, можно ли выносить.  
3) Выбирайте внутренний контур.
